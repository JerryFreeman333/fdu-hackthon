# 老人端四页重塑 · 本轮交付与接入边界

## 页面与交互

- 首页：长按麦克风开始浏览器语音识别，松开或语句识别结束后进入对话并发送一次。另有打字入口、家庭空间入口、健康入口和今日待办。
- 药物：正在使用 / 曾经使用 / 全部；添加、查看、编辑、停止使用；保存每次剂量（含原单位）、服用时间、用途说明。未知剂量不推算。旧字符串药物兼容显示，结构化记录通过原有 profileStore 保存。
- 健康档案：六种分类；拍照/图片/PDF附件保存到本机 IndexedDB，支持刷新后读取、图片预览、原文件下载。图片可交给既有识别接口，识别结果确认后才进入健康记录。
- 我的：本机账号状态、编辑个人信息、家属绑定、权限、服务连接状态。既有家属端保留。
- 新用户：选择角色 → 登录入口 → 本机建档 → 称呼、年龄、性别、基础病、用药 → 进入首页。语音填表需要用户检查后保存。

## 路线二的 Agent 端口

代码：`src/agent-tools/registry.ts`、`HomeTwinTool.ts`、`intentRouter.ts`。

工具契约：`{ name: 'home.find_item', input: { query: string } }`。

现有 API：`GET {VITE_HOME_TWIN_API_URL}/api/route2/items/find?q=...`。
返回：`status`、`dataMode`、`message`、`item.id/title/location`。
模型页面：`{VITE_HOME_TWIN_URL}/?role=resident&find=<item.id>`。

三个入口：主页空间 → 空间入口页；药物详情找药 → 工具查询 → 空间结果页；对话找物 → 同一工具 → 空间结果页。点击结果中的链接再进入路线二模型页面。没有重新开发路线二建模流程。

当前工具选择是本地意图路由，不是声称已实现大模型 function calling。带健康不适词的输入优先保留在健康处理链。路线二目前仍可能返回演示物品，页面必须保留数据来源标识。真实用户 / 家庭 / 药物 ID 绑定、精确位置与模型版本尚需路线二后端契约升级。

## 未完成的真实后端能力（不能当成已上线）

- 微信：只有登录入口及未配置提示，没有 OAuth 服务/账号会话，不能宣称登录成功。
- 健康：保留 `VITE_HEALTHKIT_ENDPOINT` 和现有手机桥接；浏览器无法仅靠按钮获得 iOS 健康权限。
- 图片识别：保留 `VITE_HEALTH_VISION_ENDPOINT`。个人模式未配置时拒绝演示识别；演示模式仍明确提示示例结果。现有解析适配器主要处理测量/检验数值，不等于完整影像诊断或任意病历全文 OCR。
- 附件和药物：本机持久化，不是云端档案。服用时间字段不等于系统后台定时推送。
- 语音：浏览器 SpeechRecognition 能力与网络/权限相关；不支持时保留文字输入。不等同于已接入自建流式 ASR。
- 对话模型：沿用 `VITE_AGENT_LLM_ENDPOINT`，未配置则沿用规则适配器，不宣称所有回答来自大模型。
- 房间视频上传、云端高斯重建、动态加载每户模型、室内实时导航本轮不实现。
