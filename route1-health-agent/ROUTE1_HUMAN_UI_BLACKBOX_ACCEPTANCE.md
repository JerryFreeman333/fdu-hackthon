# Route 1 真人 UI 黑盒验收（当前版）

> 本脚本只验证 Demo 的用户可见行为、状态边界、隐私和可恢复性，不证明医疗诊断安全。

## 当前 Demo 状态边界

- 当前角色、家庭绑定、共享同意、邀请码、one-time grant 只存在当前页面会话。
- 健康 events、family events、chat、任务也只存在当前 Demo 会话内存。
- 刷新/重新打开页面会重新开始会话，不恢复上一会话的敏感数据。
- `localStorage` 不得作为身份、授权、健康档案或任务状态恢复机制。
- 真实产品仍需要服务端账号、老人 ID、家庭关系、授权记录和服务端数据过滤。

## 通过门槛

任一项出现均为 P0/P1：

1. 别人的健康事实进入老人本人健康记录。
2. `private` 内容进入家属视图。
3. `familyEligible !== true` 的 finding 产生家属通知。
4. one-time grant 在刷新/重新进入后复活。
5. 更正 A 删除独立事实 B 或产生 ghost finding。
6. 同一天的 medication-check 任务重复生成。
7. 历史 private finding 使今日独立 urgent finding 消失。
8. 新会话看到上一会话输入、任务或家属事实。

## A. 主体归属

### A-01 第三人称

输入：`我觉得他喘得厉害`

预期：不得写入老人本人健康流；主体不明确时必须 `unknown`/澄清。

### A-02 唯一家属上下文

先输入：`我爸今天走路不稳`，再输入：`我觉得他喘得厉害`

预期：第二条可以继承爸爸，但绝不能写成老人本人事件。

### A-03 多家属上下文

先输入爸爸和丈夫的不同事实，再输入：`我觉得他喘得厉害`

预期：继续 fail-closed，不得猜测主体。

### A-04 混合主体

输入：`我爸今天没吃降压药，我也没吃`

预期：爸爸与老人本人保持两条独立 claim；本人漏服事实不得丢失。

### A-05 比较式改善

输入：`今天没有像昨天那样喘得厉害了`

预期：属于今天的改善，不得变成“今天完全没有喘”，日期不得偷换成昨天。

## B. 隐私与家属披露

### B-01 默认拒绝

老人输入普通健康事实但未授权家属。

预期：家属端不得看到该详细健康事实。

### B-02 明确可共享 urgent

老人明确允许必要家属协同，然后产生明确可共享的安全事件。

预期：家属只看到必要提醒、为什么现在通知和建议行动；不得显示完整健康档案或内部风险分数。

### B-03 private 事件

输入：`上周摔了一下，先别告诉孩子们`

预期：老人端仍可保留安全提醒；家属端不得看到该事实。

### B-04 历史 private 隔离

先记录历史 private 跌倒，再记录今天明确允许共享的跌倒。

预期：今天的独立 urgent finding 仍存在并按今天的证据决定家属资格。

## C. One-time / revoke

### C-01 一次性分享

明确授予某一 finding/event 一次性家属查看权限。

预期：只有当前 claim 后可见；重复刷新或重新进入不能复活旧 grant。

### C-02 private 覆盖

即使存在错误/旧 one-time ID，`private` 数据也不能进入家属端。

### C-03 revoke

撤销共享后，当前家属视图立即停止显示未授权数据；已建立的家属关系不被无故删除。

## D. 更正与幂等

### D-01 精确更正

产生事实 A、事实 B，再更正 A。

预期：A 消失/修正，B 保持不变。

### D-02 ghost finding

产生会触发 finding 的事实，再纠正原事实。

预期：finding 根据当前事件流重新计算，不留下旧 finding。

### D-03 medication task

同一天重复发送漏服药表述。

预期：只有一个 `task-medication-${today}`；已完成任务也不得复制。

## E. 会话隔离（新增最终门槛）

### E-01 刷新隔离

1. 老人端输入唯一探针文字，例如 `刷新隔离探针-不要恢复`。
2. 刷新页面。
3. 观察首屏。

预期：重新出现角色选择；页面不得出现探针文字、上一会话任务或上一会话健康数据。

### E-02 新会话隔离

关闭当前页面后重新打开 Route 1，再选择任一角色。

预期：不得恢复上一会话的 events、familyEvents、chat 或任务。

### E-03 当前会话切换角色

老人产生事件后，在同一页面切换到家属再切回老人。

预期：共享的是同一会话数据，但权限过滤始终按照当前角色/授权边界执行。

## F. 黑盒执行

当前最终脚本：`p0-blackbox/run-final-blackbox.mjs`

兼容入口：`p0-blackbox/run-p0.mjs`，仅转发到最终脚本，不再注入 localStorage 授权。

执行方式：

```bash
cd route1-health-agent/p0-blackbox
npm install
npx playwright install chromium
npm run blackbox
```

脚本会把每项结果写入 `p0-blackbox/final-blackbox-results.json`，并保存截图到 `p0-blackbox/final-screenshots/`。

**当前环境如果未实际运行 Chromium，只能标记为 `BLOCKED`，不能将历史截图或历史结果当作当前 head 的 PASS 证据。**
