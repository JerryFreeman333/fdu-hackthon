# Phase 1 Hardening

本文件记录进入 Phase 2 前对 Route 1 的最后一轮工程硬化边界。它不是新增产品范围，而是把已经实现的隐私、检测、任务和 Demo 能力固定为可审计的工程约定。

## 隐私

`private` 表示信息仍然属于老人的个人健康上下文，但默认不进入家属视图，也不发送给外部 LLM。`no_record` 表示本次对话不进入持久健康事件。measurement 与 lab result 具有自己的 `visibility`，避免“原始文字私密、派生指标却泄露”的数据路径。

`share_family` 表示这一次明确要求分享，不会自动把持久 `familySharing` 从 `ask` 升级成 `granted`。持久共享由独立授权操作控制。

对于 `urgent + private`，当前 Demo 保持“老人端本地仍然升级，但家属端是否可见由明确共享策略决定”的产品政策；这不是由检测规则隐式突破隐私的例外。

## 检测

个人基线继续使用观察到的个人分布。Population SD 是有意选择，不作为临床统计估计器。零方差窗口使用指标级最小容差计算偏离程度；这些容差只用于 Demo 的状态变化检测，不是临床诊断阈值。

Fusion 分类固定为四类：活动、主观症状、容量/睡眠、生理指标。每个信号族最多贡献一个类别，以避免重复计票。

## Agent

安全等级与升级仍由确定性规则引擎决定。外部 LLM 只承担自然语言表达。发送到外部 LLM 前会显式过滤私密 observation、measurement、lab 和非共享 Finding；HTTP adapter 本身也拒绝 `private` / `no_record` 输入，防止未来调用方绕过上层选择。

LLM 输出经过后置检查：空文本、超长、明显疾病诊断和自行加减停换药等表述都会回退到规则回复。

## Demo 输入

`DemoImageHealthParser` 明确是 Demo seam：它不读取图像像素，也不冒充真实 OCR，而是按用户选择的数据类型返回可重复的示例值，并记录 confidence。真实 OCR/Vision 仍通过 `ImageHealthParser` 接口后续接入。

自然语言结构化数值目前覆盖血压、体重、睡眠时长、心率、步数和夜间醒来，并对中文数字、阿拉伯数字、小数及区间做回归测试；模糊数量不猜测。

## 任务与周报

Finding 生成的任务 ID 以稳定 `ruleId` 为基础，避免持续问题跨天重复创建。周报接受任务状态并显示已完成、待处理和已忽略事项。
