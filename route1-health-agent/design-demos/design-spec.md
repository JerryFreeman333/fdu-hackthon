# 安康 Agent 移动端视觉方向稿 · 共同设计规格

## 产品与任务

安康 Agent 是面向老人及其家属的状态变化发现与行动协同产品。它不把老人简化为一组医疗数字，也不承担诊断职责；产品首先认识一个人平时的活动、睡眠、步行、主诉和家庭环境，在连续变化值得注意时才给出解释与行动建议。当前代码已经具备老人聊天、语音输入、拍照录入、个人基线、变化检测、今日任务、家庭授权、家属通知、用药确认、周报、HealthKit 接入和 Route 2 居家 3D 安全能力。本轮视觉工作不能用虚构页面替代这些真实链路，也不能因为追求参考图外观而破坏隐私门控、安全分级或既有测试契约。

## 目标受众与场景

老人端主要面向 65 岁以上、可能存在视力下降、精细操作困难或不熟悉复杂 App 导航的用户。典型场景是早晨查看今天要做的事情、用自然语言说出身体感受、用相机记录血压和报告、在紧急情况下直接联系家属或医生。家属端面向成年子女，主要场景是快速判断“今天是否有一件值得介入的事”，了解证据与建议行动，确认通知、处理用药与居家安全任务，而不是浏览全部隐私数据。

## 核心页面与信息

第一组方向稿统一展示三个最关键界面：老人首页、AI 助手、家属首页。老人首页必须出现真实身份“王秀兰奶奶”、今日任务、语音主入口、紧急求助入口，以及健康/隐私二级入口。AI 助手必须使用仓库真实对话语料，体现语音状态、建议问题、回复分块和文本输入。家属首页必须忠实呈现当前 Demo 的变化状态，不使用“本周状态良好”掩盖最近活动下降、走路喘、夜间活动增多和脚踝肿等事实；必须给出联系老人、联系社区医生、确认提醒或处理居家安全行动的可执行入口。

## 视觉语境

用户提供的九张参考图是视觉母版，不是额外功能说明。共同视觉语言为冷白到淡蓝的雾面背景、低边界白卡、柔和大圆角、清晰深色中文排版、蓝色主操作、少量粉红/薄荷绿/薰衣草色承担健康、空间和隐私语义。界面应接近现代 iOS 健康产品，但不能机械复制系统状态栏或把 Apple 品牌素材当作自有资产。老人端字号、触控热区和文案长度优先于像素复刻；正文不低于 14px，主要按钮不低于 52px，关键操作不能只靠颜色区分。

## 三个方向的探索维度

方向 A 是“参考图高还原”：最大程度保留今日待办、蓝色语音球、柔和双入口和家属宫格，验证用户最初想象能否直接落地。方向 B 是“适老优先”：仍使用同一套蓝白语言，但把语音与 SOS 提到首屏，减少同屏卡片数量，提高字号和对比度。方向 C 是“比赛叙事优先”：把个人基线发现、Agent 解释、家属行动三段闭环做成最强视觉母题，让评委在三十秒内理解技术价值。三版使用相同真实内容与相同尺寸，但布局骨架不同，避免只换色的假变体。

## 技术与接口约束

正式实现以最新 `origin/main` 为基线并合入 HealthKit 分支。统一主应用预计运行在 5173，Route 2 Web 在 5174，Route 2 FastAPI 在 8010，HealthKit Bridge 在 8787，可选 PeerJS 信令在 9000。方向稿只验证视觉，不直接发请求；正式 React 接入时必须继续使用现有 hooks、类型、环境变量与安全门控。Route 2 入口通过可配置 URL 跳转，LLM、Vision、HealthKit 和信令地址不得硬编码进表现组件。

## 输出

每个方向交付一个独立 HTML，画布为 1536×960，平铺三台 393×852 的 iPhone 15 Pro 逻辑屏。设备框统一使用 Huashu Design 的 `IosFrame` 结构。方向稿具备最小点击反馈：底部导航、语音按钮、建议问题和家属行动可点击；截图用于横向评审。用户选择方向后，才将其拆成生产级 React 组件并接入仓库。
