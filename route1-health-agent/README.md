# 安康 Agent（路线一：老年健康 Agent 原型）

> 把老人模糊的"我最近有点累"，变成可被持续观察的数据变化。

这是 fdu-hackthon **路线一**的可运行原型：一个面向老年人的健康 Agent，不做疾病诊断，只做一件事——**发现"和平时不一样"**，并在合适的时机告诉合适的人。

## 核心理念

1. **个人基线**：不跟"60 岁标准值"比，只跟王奶奶自己过去两周比。数据点不够就沉默，不硬凑阈值。
2. **多源整合**：聊天主诉 + 手表（步数/步速/睡眠/心率/血氧）+ 拍照录入（血压计/体重秤/血糖仪/体检报告）放进同一份长期档案。
3. **变化融合**：单一指标偏了不算数，"主诉 + 数据"多个信号同时对上才升级——原型内置了演示场景"活动耐量下降（心衰前兆信号）"。
4. **分级通知**：小提示/持续观察 → 只留在老人应用里；建议关注/紧急 → 才通知家属，且附证据链和"该做什么"。

## 演示场景（原型内置）

王秀兰奶奶，72 岁，高血压 + 心功能减退随访中：

- 前 16 天数据平稳，构成个人基线；
- 最近 5 天：步数骤降 ~55%、步速变慢、夜醒 1→4 次、静息心率 72→84、体重 5 天涨 1.5kg、血氧略降；
- 同时她在聊天里说"今天很累""走路有点喘""睡不好""脚有点肿"；
- Agent 把主诉与数据融合 → 产生 **alert** 级发现 → 给女儿推送：
  "最近三天活动量持续下降约 55%，建议今晚联系一下老人"；
  若水肿 + 体重快速上升同时出现 → 升级 **urgent**，给出就医路径。

打开应用即可看到这个状态；在聊天框输入（或点快捷按钮）"刚才摔了一跤"，可以看到紧急通知链路。

## 运行

```bash
cd route1-health-agent
npm install
npm run dev
```

浏览器打开提示的地址（默认 http://localhost:5173）。

## 功能一览

| 页面 | 内容 |
|------|------|
| 和阿安聊天 | 规则解析老人主诉（累/喘/睡不好/水肿/头晕/漏服药/跌倒…），共情回应并记录 |
| 健康档案 | 21 天指标趋势 + 个人基线参考线 + 最近 3 天高亮；拍照录入（模拟 OCR）；记录时间线 |
| 每周周报 | 一周数据 vs 个人基线 + 主诉汇总 + 需要留意的变化；自动生成"给子女的版本" |
| 家属通知 | 已推送通知（含证据链、建议处理路径）+ "暂不打扰家属"的观察 |

## 工程结构与接入点

```
src/
  types.ts           领域模型（指标/记录/观察/发现）
  engine/
    baseline.ts      个人基线（滚动窗口均值±标准差）
    detect.ts        变化检测 + 融合规则（输出证据链）
    escalate.ts      分级通知策略（谁该被打扰）
    report.ts        周报生成
    agent.ts         对话解析与回复（含 LlmAdapter 接口）
  data/demo.ts       21 天模拟数据 + 演示故事线
  components/        四个页面 + SVG 趋势图
```

后续接入真实能力时，只需替换三处，界面与引擎不动：

- **大模型**：`engine/agent.ts` 的 `LlmAdapter` 接口（当前为规则实现）→ 换成任意 LLM API，主诉识别会更准、回复更自然；
- **设备数据**：`data/demo.ts` 的记录源 → 换成华为/小米健康、Apple HealthKit 等同步；
- **拍照识别**：`App.tsx` 的 `PHOTO_SAMPLES` → 换成真实 OCR / 多模态模型。

## 边界与原则（重要）

- **不做 AI 诊断**：所有输出都是"状态变化提示"，就医建议只给路径不做结论；
- **不过度监控**：只在 alert/urgent 时通知家属，老人知情且可控；
- **原型内全部为模拟数据**，不含任何真实个人信息。
